# Student Support Patterns

Use this reference when deciding what kind of AAC or classroom support to build.

## Pattern Selection

- **Yes/no board**: 2 to 4 options such as Yes, No, More, Finished. Use for quick responses, preference checks, comprehension checks, and partner-assisted choice.
- **Choice board**: 4, 6, 9, or 12 options. Use for preferences, activity choices, feelings, needs, and curriculum responses. Keep one concept per button.
- **Core words board**: Stable locations for high-frequency words such as want, more, help, stop, go, finished, like, different, again. Do not rearrange core positions casually between resources.
- **First-then board**: Two large cells with clear sequencing language. Use for transitions, routines, and task framing. Avoid making it only a compliance tool.
- **Visual schedule**: Ordered routine steps. Use consistent reading and scan order. Avoid tiny timetable layouts for gaze or switch users.
- **Quiz or comprehension board**: One prompt with 2 to 4 answer choices. Always include a non-punitive response such as I don't know, Help, or Show me.
- **Book reader**: One idea per page with stable Next/Back/Finished positions. Keep navigation in the same location across pages.
- **Writing or sentence support**: Use word banks, starters, core words, fringe vocabulary, and speak-back. Keep edit controls separate from student selection controls.
- **Needs/pain/support board**: Include Help, Stop, Break, Pain, Toilet, Drink, Position, Too loud, Finished, and Other where appropriate. Treat as communication access, not behaviour management.

## Vocabulary And Symbols

- Use a mix of core vocabulary and activity-specific fringe vocabulary.
- Prefer meaningful local vocabulary: real classrooms, real staff names when appropriate, actual equipment, preferred activities, and familiar routines.
- Use photos or teacher-owned images for people, places, and local objects when generic symbols would be confusing.
- Use symbols for short labels and phrases. Avoid symbolating long paragraphs into visual clutter.
- Keep labels short, direct, and speakable. Use the student's language and dialect where known.
- Offer a way out: Stop, Help, Different, Finished, Back, or Not that.

## Interaction Design

- Put the most important communication options in stable, easy-to-access locations.
- Keep page navigation consistent. A Next button should not jump around between related pages.
- Avoid dense toolbars in student mode. Teacher controls belong in an editor, side panel, locked details element, or separate screen.
- Use calm feedback: a clear spoken label, visible selected state, and short message are usually enough.
- Avoid continuous decorative animation. Motion should communicate state or completion.
- Make accidental activation recoverable. A Back, Undo, Clear, or confirm path matters more than fancy visual design.

## Print And Low-Tech Use

- Printable boards should have strong borders, large labels, high contrast, and attribution.
- Do not rely on colour alone. Printed black-and-white output should still communicate state and grouping.
- Include enough whitespace for cutting, laminating, pointing, or partner-assisted scanning.
- If a digital board uses a multi-page structure, consider exporting one summary page or a teacher reference sheet.

## Student Dignity Checks

- Does the tool let the student initiate, refuse, repair, comment, ask, and choose, not only answer adult questions?
- Does it include real reasons a student would communicate in this setting?
- Does the output avoid infantilising language when the student is older?
- Does it make the teacher's job easier without reducing the student's agency?
- Is there a way to pause, rest, or say no?

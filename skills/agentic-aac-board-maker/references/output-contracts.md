# Output Contracts

Every output derives from canonical AAC Board IR 0.4.0. The IR is the design source; HTML, Open AAC Studio JSON and OBF/OBZ are disposable deterministic renders.

## Contract 0 — Canonical IR

- Pass `scripts/canonicalize_board_ir.py <ir> --check`.
- Pass `references/aac-board-ir.schema.json` and `scripts/validate_board_ir.py`.
- Contain no target-renderer aliases.
- Include total target limits, student/setup controls, system fit, teacher notes, symbol review strategy, privacy and attribution.
- Use explicit action objects and globally unique page/button ids.

## Contract A — Single-File HTML

- Generated by `scripts/render_html.py`; no hand edits.
- One offline file with inline CSS, canonical IR and the exact shared dwell runtime.
- Semantic buttons, visible focus, keyboard/click fallback and immediate dwell cancellation.
- Live total-target audit; setup and speech are exclusive phases.
- Working navigation/message actions, TTS failure state and large Stop Speech target.
- Teacher notes/attribution outside normal student mode; print stylesheet; no sensitive data.
- Pass `scripts/validate_html_parity.py`, static HTML checks and browser/device tests.

## Contract B — Open AAC Studio JSON

Use only for explicit compatibility. Generate with:

```sh
python3 scripts/render_open_aac_studio.py board.ir.json board.open-aac-studio.json
```

Keep target-specific `app`, `settings`, `accessibility`, `gridRows/gridColumns` and `licences` fields in this export—not in canonical IR.

## Contract C — OBF/OBZ

Generate interoperable AAC output with:

```sh
python3 scripts/render_obf.py board.ir.json board.obf   # one page
python3 scripts/render_obf.py board.ir.json board.obz   # multiple pages
```

Verify navigation, message-action mapping, symbols and licensing in the intended importing application.

## Contract D — Printable Board

Include large labels, strong borders, declared scan/pointing order, partner wait-confirm note, attribution and black-and-white readable print CSS. Printable status does not waive communication, privacy or symbol-review requirements.

## Contract E — Resource Pack

```text
<fixture-or-resource-id>/
  README.md
  <slug>.ir.json
  <slug>.html
  <slug>.open-aac-studio.json       # when useful
  <slug>.obf or <slug>.obz          # when useful
  teacher-notes.md
  symbol-review.json/html           # while candidate review is pending
```

README states purpose, access, established-system relationship, customisation, privacy, source IR, real-device/team checks and unresolved `systemFit` items.

## Fresh-Output Gate

Evaluate newly generated candidate folders, not only committed golden outputs:

```sh
python3 scripts/evaluate_fresh_output.py <candidate-root> --report evaluation-report.json
```

The harness requires canonical/schema-valid IR, semantic validation, HTML/IR/runtime parity, expected artifacts and fixture-specific communication/access/resource checks. A golden fixture passing does not prove a newly generated resource passes.

## File Naming And Handoff

Use anonymous lowercase slugs; no student names or sensitive diagnostic/behaviour wording. On handoff, state the resource, access path, communication purpose, curriculum link if relevant, how to open/print, symbol-review status and what still needs actual student/device/team testing.
